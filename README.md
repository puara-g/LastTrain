# 🚇 지하철 막차 계산기

출발역과 도착역을 입력하면 **환승 경로와 막차 시간을 확인하고, 환승까지 고려했을 때 몇 시까지 탑승해야 하는지 계산해주는 웹앱**입니다.

처음에는 일부 역의 막차 시간만 조회할 수 있도록 구현했지만, 실제로 사용해보니 등록되지 않은 역에서는 제대로 조회되지 않는 문제가 있었습니다.
이를 해결하기 위해 역명을 기준으로 역외부코드를 자동으로 조회하고, 실제 API 조회가 가능한 역은 공식 데이터를 우선 사용하도록 구조를 변경했습니다.

또한 단순히 막차 시간을 보여주는 데서 끝내지 않고, **환승에 필요한 시간과 다음 열차 시간을 고려해 사용자가 실제로 몇 시까지 이동해야 하는지 역산**하도록 구현했습니다.

* **Frontend**: `frontend/` — React + Vite
* **Backend**: `backend/` — Node.js + Express
* **Deploy**: Vercel + Render
* **Repository**: [LastTrain](https://github.com/puara-g/LastTrain)

---

## ✨ 주요 기능

### 🚉 역별 막차 조회

역명을 검색하면 해당 역의 막차 시간과 남은 시간을 확인할 수 있습니다.

공식 API에서 데이터를 가져올 수 있는 경우 `official`로 표시하고, API에서 제공되지 않는 경우에는 추정값을 사용해 `estimated`로 구분합니다.

### 🔎 역외부코드 자동 조회

처음에는 자주 사용하는 15개 역의 역외부코드(FR_CODE)를 직접 등록했습니다.

하지만 이 방식에서는 등록되지 않은 역을 검색할 때 막차 정보를 가져올 수 없었습니다.

그래서 역명을 입력하면 역 검색 API를 통해 FR_CODE를 찾아오도록 변경했습니다.

```text
역명 입력
   ↓
역 검색 API
   ↓
FR_CODE 조회
   ↓
막차 API 요청
   ↓
공식 데이터 반환
```

조회한 역외부코드는 캐시하여 같은 역을 반복해서 검색할 때 불필요한 API 호출을 줄였습니다.

---

### 🗺️ 출발역 → 도착역 경로 탐색

1~9호선 노선망을 기반으로 출발역에서 도착역까지의 경로를 탐색합니다.

역을 노드로 보고 이동 가능한 구간에 가중치를 부여한 뒤 **Dijkstra 알고리즘**으로 경로를 계산했습니다.

6호선 응암순환선처럼 일반적인 양방향 노선과 다른 구조도 노선 데이터에 반영했습니다.

---

### 🔄 환승 시간 적용

환승역에 도착했다고 바로 다음 노선을 탈 수 있는 것은 아니기 때문에 환승에 필요한 시간을 별도로 계산했습니다.

서울교통공사 공식 데이터를 이용해 **74개 역, 108개 노선 조합**의 환승 소요시간을 적용했습니다.

같은 역이라도 환승하는 노선에 따라 시간이 다르기 때문에 단순 평균값을 사용하지 않고 노선 조합별 값을 적용했습니다.

예를 들어 서울역에서도 1호선 → 4호선과 1호선 → 공항철도의 환승시간을 동일하게 계산하지 않습니다.

공식 데이터에 없는 조합은 해당 역에서 사용할 수 있는 중앙값을 사용하고, 역 자체의 데이터가 없는 경우 기본값을 사용하도록 처리했습니다.

---

### ⏰ 탑승 마감 시각 계산

이 프로젝트에서 가장 중요하게 구현한 기능입니다.

단순히

> "이 역의 막차는 00:10입니다."

라고 알려주는 것이 아니라,

**도착지에서 필요한 시간부터 거꾸로 계산해서 출발역에서 몇 시까지 이동해야 하는지**를 보여줍니다.

```text
도착역 막차
   ↑
환승 소요시간
   ↑
다음 열차 출발시간
   ↑
이전 역 도착시간
   ↑
사용자가 출발해야 하는 시간
```

이를 통해 사용자가 막차를 놓치지 않기 위해 **언제까지 역에 도착해야 하는지** 확인할 수 있도록 했습니다.

계산 과정에서 실제 열차 시간과 계산상 필요한 시간을 구분하여 표시하도록 했습니다.

---

### 🚪 빠른 하차 정보

역에 도착했을 때 빠르게 이동할 수 있도록 출구와 승강장 내 최적 하차 위치 정보를 제공합니다.

빠른하차 API의 호출량을 줄이기 위해 조회 결과를 캐시해서 사용합니다.

---

### 🏷️ 데이터 출처 표시

막차 정보는 항상 같은 신뢰도의 데이터가 아니기 때문에 화면에서 출처를 구분합니다.

| 상태          | 의미                      |
| ----------- | ----------------------- |
| `official`  | 외부 API에서 실제 데이터를 가져온 경우 |
| `sample`    | 개발용 표본 데이터를 사용하는 경우     |
| `estimated` | 공식 데이터를 사용할 수 없어 추정한 경우 |

특히 2호선처럼 외부 API에서 데이터를 제공하지 않는 경우 무조건 실제 데이터인 것처럼 보여주지 않고 `estimated`로 구분했습니다.

# 🔧 개발하면서 해결한 문제

## 1. 등록되지 않은 역은 막차 조회가 되지 않는 문제

### 처음 구현했을 때

처음에는 15개 역의 FR_CODE를 직접 등록해 사용했습니다.

```text
강남역 → 0222
시청역 → 0151
서울역 → ...
```

이 방식은 구현하기는 간단했지만 등록하지 않은 역을 검색할 수 없다는 문제가 있었습니다.

### 해결

역명을 입력하면 먼저 역 검색 API를 호출해 FR_CODE를 가져오도록 변경했습니다.

```text
사용자 검색
    ↓
역명 검색 API
    ↓
FR_CODE 확인
    ↓
막차 API 호출
```

그리고 같은 역을 다시 검색했을 때 API를 반복 호출하지 않도록 캐시를 적용했습니다.

결과적으로 미리 등록한 역 외에도 노선망에 포함된 역을 API를 통해 조회할 수 있도록 구조를 변경했습니다.

---

## 2. 2호선 막차 데이터가 계속 조회되지 않는 문제

2호선의 여러 역을 대상으로 평일과 주말 데이터를 반복해서 테스트했지만 API에서 계속 `INFO-200 데이터 없음` 응답이 반환됐습니다.

처음에는 역외부코드가 잘못된 것으로 생각했지만, 같은 방식으로 조회한 다른 노선에서는 정상적으로 데이터가 반환됐습니다.

그래서 역코드 자체의 문제보다는 **외부 API에서 제공하는 데이터 범위의 문제**로 판단했습니다.

코드에서 억지로 실제 데이터처럼 처리하기보다는 2호선은 추정값으로 처리하고 화면에서 `estimated` 상태를 표시하도록 했습니다.

---

## 3. 환승시간을 평균값으로 계산했을 때 오차가 발생

처음에는 환승시간을 하나의 평균값으로 계산했습니다.

하지만 실제로 테스트해보니 같은 역에서도 환승 노선에 따라 필요한 시간이 달랐습니다.

예를 들어 서울역에서

```text
1호선 → 4호선
1호선 → 공항철도
```

의 환승시간을 동일하게 계산하면 실제 이동시간과 차이가 생길 수 있었습니다.

그래서 서울교통공사 공식 환승 소요시간 데이터를 적용하고, **역과 노선 조합별로 다른 환승시간을 사용하도록 변경했습니다.**

데이터에 없는 조합은 중앙값 → 기본값 순서로 fallback하도록 구현했습니다.

---

## 4. 실제 막차 시간과 계산상 마감 시간이 섞이는 문제

막차를 역산하는 과정에서 어떤 구간은 실제 열차 시간이고, 어떤 구간은 다음 환승을 고려했을 때 필요한 계산상의 시간이었습니다.

두 값을 하나의 시간처럼 보여주면 사용자가 실제 열차 시간으로 오해할 수 있기 때문에 구분해서 표시했습니다.

즉,

* 실제 API에서 확인된 열차 시간
* 환승을 고려해 계산된 마감 시간

을 별도로 처리했습니다.

# ⚠️ 현재 한계

현재 구현에는 몇 가지 한계가 있습니다.

### 노선 데이터

`lineStations.json`은 위키백과를 기반으로 조사한 데이터이기 때문에 일부 구간은 실제 노선도와 추가 대조가 필요합니다.

특히 1호선 도봉산~구로 구간이나 4호선 진접선 등의 경계는 실제 운행 데이터를 기준으로 다시 검증할 필요가 있습니다.

### 구간 이동시간

환승시간은 공식 데이터를 적용했지만, 역과 역 사이의 이동시간은 현재 역당 평균 약 2.5분을 기준으로 추정하고 있습니다.

향후 실제 열차 시간표를 이용해 구간별 이동시간을 적용하면 더 정확한 경로 계산이 가능할 것으로 보입니다.

### API 호출 제한

서울 열린데이터광장 API에는 일일 호출 한도가 있습니다.

현재는 빠른하차 정보를 캐시하고 있으며, 실제 사용자가 증가한다면 역 코드와 막차 조회 결과 등에도 캐싱을 확대할 필요가 있습니다.

### Render 콜드 스타트

백엔드를 Render 무료 플랜으로 배포했기 때문에 일정 시간 요청이 없으면 서버가 sleep 상태가 될 수 있습니다.

이 경우 첫 요청에서 응답시간이 길어질 수 있습니다.

`backend/.env`에 서울 열린데이터광장 API 키를 입력합니다.

```env
SEOUL_API_KEY=YOUR_KEY
SEOUL_API_SERVICE=SearchLastTrainTimeByFRCodeService
SEOUL_API_STATION_SEARCH_SERVICE=SearchInfoBySubwayNameService
SEOUL_API_QUICK_EXIT_SERVICE=getFstExit
```

API 키가 없는 경우 개발용 표본 데이터와 fallback 로직으로 동작하도록 구성했습니다.

# 💡 프로젝트를 통해 배운 점

이번 프로젝트에서는 단순히 API를 호출해 데이터를 화면에 표시하는 것보다, **외부 데이터가 항상 완전하거나 정확하지 않을 수 있다는 점**을 많이 경험했습니다.

특히 역외부코드 조회, 2호선 데이터 누락, 환승시간 차이 등의 문제를 해결하면서 API의 응답만 믿기보다 실제 여러 조건에서 테스트하고 fallback을 설계하는 과정이 필요하다는 것을 알게 되었습니다.

또한 막차 시간을 보여주는 것에서 끝내지 않고 사용자가 실제로 이동할 수 있는 시간으로 바꾸기 위해 **경로 탐색, 환승시간, 막차 시간을 하나의 계산 과정으로 연결**하는 데 집중했습니다.

앞으로는 실제 열차 운행시간을 기반으로 역간 이동시간까지 보완하고, 더 다양한 노선과 데이터를 적용해 실제 사용 환경에서도 안정적으로 사용할 수 있는 서비스로 발전시키고 싶습니다.
