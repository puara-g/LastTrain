# 🚇 지하철 막차 계산기

출발역과 도착역을 입력하면 **환승 경로와 막차 시간을 확인하고, 환승까지 고려했을 때 몇 시까지 탑승해야 하는지 계산해주는 웹앱**입니다.


* **Frontend**: `frontend/` — React + Vite
* **Backend**: `backend/` — Node.js + Express
* **Deploy**: Vercel + Render
* **Repository**: [LastTrain](https://github.com/puara-g/LastTrain)

---

## ✨ 주요 기능

### 🚉 역별 막차 조회

역명을 검색하면 해당 역의 막차 시간과 남은 시간을 확인할 수 있습니다.

공식 API에서 데이터를 가져올 수 있는 경우 `official`로 표시하고, API에서 제공되지 않는 경우에는 서울교통공사가 공개한 실제 열차운행시각표를 참고해 `timetable`로, 그마저 없으면 추정값을 사용해 `estimated`로 구분합니다.


---

### 🗺️ 출발역 → 도착역 경로 탐색

1~9호선 노선망을 기반으로 출발역에서 도착역까지의 경로를 탐색합니다.

역을 노드로 보고 이동 가능한 구간에 가중치를 부여한 뒤 **Dijkstra 알고리즘**으로 경로를 계산했습니다.

6호선 응암순환선처럼 일반적인 양방향 노선과 다른 구조도 노선 데이터에 반영했습니다.

---

### 🔄 환승 시간 적용

환승역에 도착했다고 바로 다음 노선을 탈 수 있는 것은 아니기 때문에 환승에 필요한 시간을 별도로 계산했습니다.

서울교통공사 공식 데이터를 이용해 **74개 역, 108개 노선 조합**의 환승 소요시간을 적용했습니다.

같은 역이라도 환승하는 노선에 따라 시간이 다르기 때문에 단순 평균값을 사용하지 않고 노선 조합별 값을 적용했습니다.

예를 들어 서울역에서도 1호선 → 4호선과 1호선 → 공항철도의 환승시간을 동일하게 계산하지 않습니다.

공식 데이터에 없는 조합은 해당 역에서 사용할 수 있는 중앙값을 사용하고, 역 자체의 데이터가 없는 경우 기본값을 사용하도록 처리했습니다.

---

### ⏰ 탑승 마감 시각 계산

이 프로젝트에서 가장 중요하게 구현한 기능입니다.

단순히

> "이 역의 막차는 00:10입니다."

라고 알려주는 것이 아니라,

**도착지에서 필요한 시간부터 거꾸로 계산해서 출발역에서 몇 시까지 이동해야 하는지**를 보여줍니다.

```text
도착역 막차
   ↑
환승 소요시간
   ↑
다음 열차 출발시간
   ↑
이전 역 도착시간
   ↑
사용자가 출발해야 하는 시간
```

이를 통해 사용자가 막차를 놓치지 않기 위해 **언제까지 역에 도착해야 하는지** 확인할 수 있도록 했습니다.

계산 과정에서 실제 열차 시간과 계산상 필요한 시간을 구분하여 표시하도록 했습니다.

---

### 🚪 빠른 하차 정보

역에 도착했을 때 빠르게 이동할 수 있도록 출구와 승강장 내 최적 하차 위치 정보를 제공합니다.

빠른하차 API의 호출량을 줄이기 위해 조회 결과를 캐시해서 사용합니다.

# 🔧 개발하면서 해결한 문제


## 1. 2호선 막차 데이터가 계속 조회되지 않는 문제

2호선의 여러 역을 대상으로 평일과 주말 데이터를 반복해서 테스트했지만 API에서 계속 `INFO-200 데이터 없음` 응답이 반환됐습니다.

처음에는 역외부코드가 잘못된 것으로 생각했지만, 같은 방식으로 조회한 다른 노선에서는 정상적으로 데이터가 반환됐습니다.

그래서 역코드 자체의 문제보다는 **외부 API에서 제공하는 데이터 범위의 문제**로 판단했습니다.

코드에서 억지로 실제 데이터처럼 처리하기보다는 2호선은 추정값으로 처리하고 화면에서 `estimated` 상태를 표시하도록 했습니다.

**(해결)** 이후 서울교통공사가 공개한 열차운행시각표 원본 데이터(엑셀/CSV)를 구해서, 이를 역·방향·요일유형별 막차 인덱스(`timetableLastTrain.json`)로 가공하는 `buildTimetable.js`를 추가했습니다. 이제 2호선처럼 `SearchLastTrainTimeByFRCodeService` API가 데이터를 주지 않는 노선도 실제 공개 시각표를 근거로 한 `timetable` 상태로 표시되고, 추정값(`estimated`)은 시각표에도 없는 최후의 경우에만 사용됩니다.

---

## 2. 환승시간을 평균값으로 계산했을 때 오차가 발생

처음에는 환승시간을 하나의 평균값으로 계산했습니다.

하지만 실제로 테스트해보니 같은 역에서도 환승 노선에 따라 필요한 시간이 달랐습니다.

예를 들어 서울역에서

```text
1호선 → 4호선
1호선 → 공항철도
```

의 환승시간을 동일하게 계산하면 실제 이동시간과 차이가 생길 수 있었습니다.

그래서 서울교통공사 공식 환승 소요시간 데이터를 적용하고, **역과 노선 조합별로 다른 환승시간을 사용하도록 변경했습니다.**

데이터에 없는 조합은 중앙값 → 기본값 순서로 fallback하도록 구현했습니다.

---

## 3. 실제 막차 시간과 계산상 마감 시간이 섞이는 문제

막차를 역산하는 과정에서 어떤 구간은 실제 열차 시간이고, 어떤 구간은 다음 환승을 고려했을 때 필요한 계산상의 시간이었습니다.

두 값을 하나의 시간처럼 보여주면 사용자가 실제 열차 시간으로 오해할 수 있기 때문에 구분해서 표시했습니다.

즉,

* 실제 API에서 확인된 열차 시간
* 환승을 고려해 계산된 마감 시간

을 별도로 처리했습니다.

---

## 4. 위키백과 기반 노선 데이터(`lineStations.json`)의 7호선 구간 누락

`lineStations.json`은 공식 자료가 아니라 위키백과를 참고해서 손으로 정리한 데이터였기 때문에, 일부 구간이 실제 노선도와 미묘하게 다를 가능성이 있었습니다.

`timetableLastTrain.json`을 만들면서 서울교통공사 열차운행시각표 원본(9개 노선 전체)을 이미 확보해둔 상태였기 때문에, 이 실제 데이터로 `lineStations.json`의 9개 노선을 전부 교차검증했습니다.

그 결과 1호선의 도봉산~구로 경계, 4호선의 진접선(진접·오남·별내별가람) 포함 여부는 실제 시각표 기준으로도 정확했습니다. 나머지 미등록 구간은 전부 코레일 직결 구간(경원선·경부선·경인선·과천선·안산선)으로, 서울교통공사가 운영하지 않는 구간이라 의도적으로 제외된 것이 맞았습니다.

다만 **7호선에서는 실제로 누락된 구간을 발견했습니다.** 기존 `lineStations.json`은 `...광명사거리, 온수`에서 끝났지만, 실제 7호선은 광명사거리~온수 사이에 **천왕**역이 하나 더 있고, 온수 이후로도 서울교통공사가 운영하는 부천·인천 방면 연장 구간이 이어집니다. 시각표 기준 실제 순서는

```text
...광명사거리, 천왕, 온수, 까치울, 부천종합운동장, 춘의, 신중동, 부천시청, 상동, 삼산체육관, 굴포천, 부평구청, 산곡, 석남
```

이며, 천왕을 포함해 총 12개 역이 빠져 있었습니다. 이 구간은 경로 탐색과 막차 방향 판별(forward/backward) 모두 `lineStations.json`의 역 순서 배열을 기준으로 계산되기 때문에, 누락된 상태로는 이 구간 이용자에게 잘못된 결과를 보여줄 수 있는 문제였습니다.

`lineStations.json`에 누락된 12개 역을 추가하고, `timetableLastTrain.json`을 다시 생성해서 해결했습니다.

## 5. 역간 이동시간을 역당 평균값으로 추정하던 문제

환승시간은 서울교통공사 공식 데이터를 적용했지만, 정작 역과 역 사이의 이동시간은 역당 평균 약 2.5분이라는 획일적인 값으로 추정하고 있었습니다. 실제로는 역간 거리에 따라 1분 만에 닿는 구간도 있고 7분 가까이 걸리는 구간도 있어서, 경로가 길어질수록 예상 소요시간과 실제 소요시간의 오차가 누적되는 문제가 있었습니다.

`timetableLastTrain.json`을 만들 때 이미 각 열차(열차코드)가 실제로 어느 역, 어느 역을 연달아 지났는지 알 수 있는 원본 데이터를 확보해둔 상태였기 때문에, 같은 열차코드로 묶인 행들을 시각 순으로 정렬해서 바로 옆 역까지 걸린 실제 시간을 계산했습니다. 급행열차가 중간역을 건너뛰어 생기는 비정상적인 값은 `lineStations.json` 기준으로 실제 인접한 역 쌍이 아니면 제외하는 방식으로 걸러냈습니다.

그 결과 `backend/data/segmentTravelTimes.json`에 전체 노선 인접 역 쌍의 99% 이상(706쌍)에 대한 실측 이동시간(1~7분)을 확보했고, `routeFinder.js`가 경로의 예상 소요시간을 계산할 때 역당 평균값 대신 이 실측값을 우선 사용하도록 변경했습니다. 데이터가 없는 극소수 구간에서만 기존 평균값으로 대체합니다.

# 💡 프로젝트를 통해 배운 점

이번 프로젝트에서는 단순히 API를 호출해 데이터를 화면에 표시하는 것보다, **외부 데이터가 항상 완전하거나 정확하지 않을 수 있다는 점**을 많이 경험했습니다.

특히 역외부코드 조회, 2호선 데이터 누락, 환승시간 차이 등의 문제를 해결하면서 API의 응답만 믿기보다 실제 여러 조건에서 테스트하고 fallback을 설계하는 과정이 필요하다는 것을 알게 되었습니다.

또한 막차 시간을 보여주는 것에서 끝내지 않고 사용자가 실제로 이동할 수 있는 시간으로 바꾸기 위해 **경로 탐색, 환승시간, 막차 시간을 하나의 계산 과정으로 연결**하는 데 집중했습니다.

앞으로는 실제 열차 운행시간을 기반으로 역간 이동시간까지 보완하고, 더 다양한 노선과 데이터를 적용해 실제 사용 환경에서도 안정적으로 사용할 수 있는 서비스로 발전시키고 싶습니다.
