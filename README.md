# 지하철 막차 계산기

역을 검색하면 오늘 기준 막차 시각과 남은 시간을 보여주는 웹앱입니다.

- `frontend/` — React + Vite
- `backend/` — Node + Express (공공데이터포털 API 프록시, API 키를 프론트엔드에 노출하지 않기 위해 필요)

## 지금 상태

`backend/.env`에 `SEOUL_API_KEY`를 넣으면 표본 15개 역뿐 아니라 **노선망에 있는 거의 모든
역**(약 300개)에서 실제 공식 데이터를 받아옵니다. 처음에는 `backend/data/mockStations.js`에
미리 등록해둔 15개 역만 실제 데이터를 썼는데, "표본에 없으면 왜 API로 직접 안 찾아보냐"는
지적을 받고 구조를 바꿨습니다. 이제 표본에 없는 역이 들어오면:

1. `backend/services/stationCodeResolver.js`가 "역명으로 지하철역 검색" API로 그 역의
   역외부코드(FR_CODE)를 즉석에서 찾고 (한 번 찾은 코드는 캐시),
2. 그 코드로 막차 API를 바로 호출해서 실제 시각을 받아옵니다.
3. 이마저 안 되는 경우에만(코드를 못 찾음, 그 노선 자체에 데이터가 없음) 가장 가까운
   표본역 기준 보간(`source: "estimated"`)으로 폴백합니다.

유일한 예외는 **2호선**입니다. 강남·잠실·시청·신도림 등 여러 2호선 역과 평일/토요일/일요일
전부로 확인해봤는데, 역코드가 맞는데도 막차 API가 항상 `INFO-200 해당하는 데이터가
없습니다`를 돌려줍니다 — **이 API 자체가 2호선 데이터를 제공하지 않는 것으로 보입니다**
(순환선이라 이 데이터셋에서 아예 빠진 것으로 추정, 코드 문제는 아닙니다). 그래서 2호선만
항상 보간(`estimated`)으로 남습니다.

API 키가 아예 없으면 전부 **샘플(예시) 데이터**(mockStations.js에 있는 15개 역 한정)로
동작합니다. 화면에 노란 경고 배너가 뜨고, 실제 막차 시각이 아니라는 점을 알려줍니다.

현재는 서울교통공사(1~9호선) 데이터만 연동하도록 설계했습니다. 신분당선·공항철도·경의중앙선 등
다른 수도권 운영사 노선까지 넓히려면 국토교통부 TAGO API(전국 지하철 시간표)를 추가로 붙이면 되는데,
이건 `backend/services/`에 파일을 하나 더 만들어 같은 방식으로 확장할 수 있습니다.

## 실제 막차 데이터로 연동하는 방법

1. **공공데이터포털(data.go.kr) 또는 서울 열린데이터광장(data.seoul.go.kr) 회원가입 및 로그인**
2. "[지하철정보]서울교통공사_역외부코드로 지하철 막차 시간표 검색" 활용신청을 누릅니다.
   (승인까지 보통 몇 분~몇 시간 걸릴 수 있어요. 목록에 이름이 비슷한 API가 여러 개 있는데,
   꼭 이 이름 그대로를 골라야 합니다 — "역코드로" 버전 등은 파라미터가 다릅니다.)
3. 승인되면 상세 페이지의 "Open API" 탭/미리보기에서 **요청 URL 예시**를 확인합니다. 실제로
   확인해보니 서비스명은 `SearchLastTrainTimeByFRCodeService`이고, 요청 형식은
   `/{키}/json/SearchLastTrainTimeByFRCodeService/1/5/{역외부코드}/{요일:1평일 2토 3일}/{상하행:1상행 2하행}`
   입니다. (이미 `backend/.env`의 기본값으로 반영해뒀습니다.)
4. `backend/.env` 파일을 열고 `SEOUL_API_KEY`에 발급받은 키를 붙여넣습니다.
5. 백엔드를 재시작하면 `backend/data/mockStations.js`에 real 역외부코드가 있는 역부터
   `source: "official"`로 응답합니다. 실패하면(가짜 코드, 네트워크 오류 등) 콘솔에 에러 로그를
   남기고 샘플/추정 데이터로 자동 폴백합니다.

### 역외부코드 확인 방법 (표본 역을 더 늘리고 싶다면)

이제 표본에 없는 역도 대부분 자동으로 실제 데이터를 받아오기 때문에(위 참고) 이 작업이
꼭 필요하지는 않습니다. 다만 (1) API 키가 없을 때 보여줄 샘플 값이 필요하거나, (2) 노선에
표본이 하나도 없어서 보간 기준점 자체가 없는 경우(예: 2호선 성수지선 같은 지선)에는 여전히
`mockStations.js`에 표본역을 하나 추가해두는 게 도움이 됩니다.

"[지하철정보]서울교통공사_역명으로 지하철역 검색"(`SearchInfoBySubwayNameService`) API를
추가로 활용신청하면 역 이름으로 역외부코드(FR_CODE)를 조회할 수 있습니다. 같은
`SEOUL_API_KEY`를 그대로 쓰면 되고, `backend/.env`에 `SEOUL_API_STATION_SEARCH_SERVICE`로
서비스명이 이미 등록돼 있습니다. 아래 스크립트로 역 이름만 넣으면 코드가 바로 나옵니다.

```bash
cd backend
node scripts/lookupStationCode.js 잠실
```

나온 FR_CODE를 `backend/data/mockStations.js`에 새 역으로 추가하면(다른 역 항목을 참고해서
`dir`도 `backend/data/lineStations.json`의 해당 호선 배열 순서에 맞게 넣어주세요) 그 역부터
바로 공식 데이터로 잡히고, 주변 역 보간(추정)의 기준점도 늘어납니다.

## 환승 경로 찾기

"환승 경로 찾기" 탭에서는 출발역/도착역을 입력하면 1~9호선 전체 노선망(약 300개 역,
`backend/data/lineStations.json`)에서 다익스트라로 최단 경로와 환승역을 찾아줍니다.

- **경로·환승역 자체는 정확합니다.** 노선도상의 역 순서를 그대로 반영했고, 6호선 응암순환처럼
  한쪽 방향으로만 운행하는 단방향 순환 구간도 반영해서 실제로 갈 수 없는 경로는 추천하지 않습니다.
- **구간별 소요시간과 환승 소요시간은 추정치입니다.** `backend/data/estimate.js`의
  `AVG_MINUTES_PER_STOP`(역당 평균 2.5분)으로 정차역 수 × 평균 시간을 계산합니다(이건 여전히
  추정치입니다). 환승 소요시간은 다릅니다 — `backend/data/transferTimes.js`가 서울교통공사가
  공개한 실제 "환승역거리 소요시간 정보"(2025.12.31 기준, 도보 초속 1.2m/s 실측) 원본 값을
  그대로 담고 있어서(74개 역, 108개 노선 조합) **실제 공식 수치**입니다. 같은 역이라도 어느
  노선끼리 환승하느냐에 따라 시간이 크게 다를 수 있어서(예: 서울역 1↔4호선은 2분이지만
  1↔공항철도는 4분) 역 이름뿐 아니라 두 노선 조합까지 같이 봐서 정확한 값을 찾습니다. 그
  역에 데이터가 있는데 노선 조합만 못 찾으면 그 역의 다른 값들의 중앙값으로, 역 자체가
  데이터에 없으면 기본값(5분)으로 근사합니다. 각 구간의 막차 시각은 버튼을 누르지 않아도
  자동으로 표시되고, 그 구간이 실제로 향하는 방향(상행/하행 중 하나)만 보여줍니다 — 이건
  `backend/services/lastTrainLookup.js`의 `directionBetween()`이 `lineStations.json` 배열에서
  출발역과 도착역의 인덱스를 비교해서 판단합니다. 또한 "환승까지 포함해서 늦어도 몇 시까지
  타야 하는지"도 `backend/services/deadlineCalculator.js`가 도착지에서부터 거꾸로 계산해서
  화면 상단에 보여줍니다: 각 구간의 실제 막차가 다음 환승을 놓치지 않으면 그 실제 시각을,
  놓친다면 "실제 열차는 아니지만 계산상 이 시각까지는 타야 한다"는 값을 대신 보여줍니다.
  구간 이동 시간까지 실측치로 바꾸고 싶으면 아래 데이터를 참고하세요.
  - [서울교통공사_역간거리](https://data.seoul.go.kr/dataList/OA-12034/S/1/datasetView.do) — 구간별
    실제 이동 시간 계산에 활용 가능
- **막차 시각은 "표본 15개 역(그중 3개는 실제 공식 데이터)" + "그 표본을 기준으로 보간 추정한
  값"입니다.** 구간 출발역이 표본 역과 정확히 일치하면 그 역의 값(공식 API 키가 있고 진짜
  역외부코드가 등록된 역이면 `source: "official"`, 아니면 `source: "sample"` 예시 시각)을 그대로
  보여주고, 표본에 없는 역이면 같은 노선의 가장 가까운 표본역 시각에서 `(정차역 차이) × 2.5분`만큼
  앞뒤로 보간해 `source: "estimated"`로 보여줍니다. 막차는 실제로 열차 한 대가 각 역을 순서대로
  지나가므로 이런 보간 자체는 합리적이지만, 기준으로 삼은 표본역이 `sample`(제가 넣은 예시 숫자)이면
  보간 결과도 진짜 막차 시각은 아닙니다. 화면에는 항상 그 사실과 "어느 역 기준으로 몇 정거장 차이로
  추정했는지"를 같이 보여줍니다. 나머지 12개 표본의 역외부코드를 실제 값으로 교체할수록(위
  "역외부코드 확인 방법" 참고) 보간 정확도도 같이 좋아집니다. 노선에 표본역이 하나도 없으면(예:
  2호선 성수지선처럼 지선 전용 구간) 보간할 기준이 없어 "표본 데이터가 없어 추정할 수도 없다"고
  정직하게 표시하고, 표본역이 종점이라 한쪽 방향 자체가 없는 경우(예: 오금역 하행)도 그 사실을
  그대로 보여줍니다.
- `backend/data/lineStations.json`은 위키백과 기반으로 조사한 데이터라 일부 경계(예: 1호선을
  도봉산~구로까지 포함시킨 것, 4호선 진접선 포함 여부 등)는 실제 노선도와 대조 확인을 권장합니다.

## 빠른하차 정보

역 막차 조회/환승 경로 찾기 결과에 "🚪 빠른하차 정보"가 같이 뜹니다. 서울 열린데이터광장의
`getFstExit` API(같은 `SEOUL_API_KEY` 사용, 별도 키 불필요)를 씁니다. 이 API는 역명으로 바로
필터링하는 기능이 없어서, 전체 데이터(약 2,300여 건)를 서버 시작 시 미리 받아 메모리에
캐시해두고(`backend/services/quickExitApi.js`) 요청이 올 때 걸러줍니다. 환승 경로에서는 그
구간이 실제로 향하는 방향의 정보만 보여주고, 역 막차 조회에서는 양방향을 다 보여줍니다.

## 로컬 실행

터미널 두 개를 열고 각각 실행하세요.

```bash
# 1. 백엔드 (http://localhost:4000)
cd backend
npm install
npm start

# 2. 프론트엔드 (http://localhost:5173)
cd frontend
npm install
npm run dev
```

프론트엔드 개발 서버는 `/api`로 오는 요청을 자동으로 백엔드(4000번 포트)로 전달하도록
`vite.config.js`에 프록시가 설정되어 있습니다.
